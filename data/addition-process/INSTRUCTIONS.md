# CCC Commentary Addition Process

This folder contains the tools for importing new CCC (Catechism of the Catholic
Church, 2nd edition) paragraphs into the commentary JSON files.

---

## Files

| File | Purpose |
|---|---|
| `commentary-unadded.txt` | Source text: paste the next batch of CCC paragraphs here |
| `catechism-import.py` | Import script (two-stage: proofread then commit) |
| `proofreading.json` | Generated by Stage 1; review before committing |
| `INSTRUCTIONS.md` | This file |

---

## Two-Stage Workflow

### Stage 1 — Generate proofreading.json

```
python data/addition-process/catechism-import.py
```

Parses `commentary-unadded.txt`, formats all entries (curly quotes, em space,
italics, footnote substitution), and writes them to `proofreading.json`. No
commentary files are touched. Review `proofreading.json` carefully before
proceeding.

### Stage 2 — Commit

```
python data/addition-process/catechism-import.py --commit
```

Reads `proofreading.json` and inserts each entry into the appropriate
`{book}/{chapter}.json` commentary file. Also calls `cleanup_previous_run()`
(keyed on the page set in `proofreading.json`) to remove stale entries from a
prior run before re-inserting.

### Update the index

```
python data/commentaries/update-index.py
```

## Preparing a New Batch

### 1. Paste the source text

Replace the contents of `commentary-unadded.txt` with the new CCC paragraphs.
Follow the format described below. Apply the pre-import text fixes listed further
down.

### 2. Update `PARA_TO_PAGE`

In `catechism-import.py`, update the `PARA_TO_PAGE` dict to map each new
paragraph number to its physical page in the CCC 2nd edition. Paragraphs that
span two pages use a string like `"86-87"`.

### 3. Run Stage 1, proofread, then commit

## Source TXT Format

The file has two sections separated by **three or more blank lines**:

```
[MAIN SECTION: numbered paragraphs and block quotes]



[FOOTNOTE SECTION: three-digit footnote numbers]
```

### Main section

- **Paragraphs** begin with a 3–4 digit number followed by a space: `355 Text…`
- **Section headers** (`I. "IN THE IMAGE OF GOD"`, `IN BRIEF`, etc.) are
  single-line blocks between blank lines. The parser skips them automatically.
- **Long quotations** (patristic citations, extended Bible quotes) follow the
  paragraph they belong to, introduced by a colon at the end of the paragraph
  line. They appear as their own block, separated by a blank line. If the
  quotation is a single long line, the parser treats it as a section header and
  skips it; its footnote references must be captured via the parent paragraph's
  ending colon + footnote number.
- **Footnote reference numbers** are superscript in the original CCC. In plain
  text they appear embedded after punctuation or directly after a word. The
  parser detects them in three ways (see "Footnote Detection" below).

### Footnote section

Each footnote begins with its 3-digit number on its own line:

```
218 Gen 1:27.
221 St. Catherine of Siena, Dialogue IV, 13: LH, Sunday, week 19, OR.
```

Multi-line footnotes are continued on indented lines (any line that does not
start with a 3-digit number is treated as continuation).

---

## Footnote Reference Detection

The parser detects footnote reference numbers (2–3 digits) using three patterns:

| Pattern | Example in source | Notes |
|---|---|---|
| After `.` `;` `"` `'` `,` | `salvation."193` / `him,231` | Standard; 2–3 digits |
| After `:` | `whole earth":226` / `Spirit:232` | 3-digit only (colon also precedes Bible chapter:verse, but those are ≤2 digits or inside parens) |
| Letter immediately before number | `earth248` / `concupiscence254` | Mid-sentence superscript refs; 2–3 digits followed by space |

When in doubt, check `proofreading.json` to verify that each paragraph's
footnotes were correctly detected.

## Pre-Import Text Fixes

Apply these corrections to `commentary-unadded.txt` before running:

### Typography

| Replace | With | Unicode | Where |
|---|---|---|---|
| `. . .` or `...` | `…` | U+2026 | All paragraphs and block quotes |
| ` - ` (space–hyphen–space) | ` — ` | U+2014 with spaces | Em dashes in prose only — not hyphens in compound words or verse ranges |

### Bible book abbreviation errors (common OCR / copy issues)

| Error | Correct | Note |
|---|---|---|
| `I Cor` | `1 Cor` | OCR: digit 1 → letter I |
| `I Jn` | `1 Jn` | OCR: digit 1 → letter I |
| `I Pet` | `1 Pet` | OCR: digit 1 → letter I |
| `1 Th` | `1 Thess` | Short form (also added to BOOK_MAP as fallback) |
| `2 Th` | `2 Thess` | Short form (also added to BOOK_MAP as fallback) |
| `Dt` | `Deut` | Alternate abbreviation (also added to BOOK_MAP as fallback) |
| `2 Macc 6 30` | `2 Macc 6:30` | Missing colon between chapter and verse |
| `66: 13` (space after colon) | `66:13` | If present — though the parser strips leading spaces, so harmless |
| `3:4- 19` (space in range) | `3:4-19` | Verse range with stray space |

### Missing period after `cf`

| Error | Correct |
|---|---|
| `(cf Eph 1:3-6)` | `(cf. Eph 1:3-6)` |

## Output Format

`proofreading.json` is an array of paragraph objects:

```json
[
  {
    "para": 355,
    "page": 91,
    "text": "355.\u2003\"God created man in his own image…\"",
    "targets": [
      { "book": "gen", "chapter": 1, "v": 27, "p": 91, "file": "gen/1.json" }
    ]
  }
]
```

Each entry in `targets` corresponds to one JSON entry that will be written to
`data/commentaries/…/{book}/{chapter}.json`.

The `text` field follows these formatting rules:

### Paragraph separator: U+2003 EM SPACE
After the paragraph number and period, U+2003 (EM SPACE) is inserted — not a
regular space.

### Quotation marks: curly quotes

| Straight | Curly | Unicode |
|---|---|---|
| `"` | `"` / `"` | U+201C / U+201D |
| `'` | `'` / `'` | U+2018 / U+2019 |

Converted by a character-by-character state machine. Apostrophes in contractions
(e.g. `God's`) are identified by being flanked on both sides by alphabetic
characters and always become U+2019.

### Italics: `<i>` tags

**Inside parentheticals** in the paragraph body, and throughout all inserted
footnote text:

- **Bible books** (see `BOOK_MAP` in the script for full list)
- **Vatican II / papal documents**: `DV`, `LG`, `GS`, `GCD`, `CPG`, `LH`, `AG`,
  `AA`, `SC`, `PO`, `UR`, `NA`, `GE`, `OT`, `PC`

To add a new document abbreviation, append it to `DOC_ABBREVS` in the script.

### Footnote substitution
Each footnote reference number in the paragraph text is replaced by the full
footnote content in parentheses, with abbreviations italicized:

```
salvation?"193  →  salvation?" (Cf. Heb 1:14.)
```

---

## Bible Reference Parsing

References are extracted from:
1. Inline parentheticals in the paragraph text
2. Footnote texts referenced by the paragraph

Each `(book, chapter, verse)` tuple generates one JSON entry in
`{book}/{chapter}.json`.

**Skipped cases:**
- Cross-chapter ranges (`Gen 1:1–2:4`)
- Bare chapter references without verse (`Gen 19`)
- Non-Bible references (`DS 902`, `PG 54`, `PL 52`, council names)

## Known Limitations

- **Single-line block quotes**: A long quotation that fits on one line in the
  source file is treated as a section header by the parser and skipped. Footnote
  references inside such a block (e.g. `Dan 3:57-80` in fn 233 for para 364)
  are not processed unless the same footnote number also appears at the end of
  the parent paragraph's main line (e.g. via the colon pattern).
  **Workaround**: add the block quote text manually to the paragraph's `text`
  field in `proofreading.json` before committing, and add any missing targets.
  **Planned fix**: detect paragraphs whose main line ends with `:` or `:\d{3}`
  (colon + footnote number) and treat the immediately following single-line block
  as a prose continuation rather than a header — section headers never follow a
  colon in this way.

- **Multi-word Latin titles**: Encyclical titles like *Humani generis* are not
  automatically italicized. They would need to be added to `DOC_ABBREVS` as
  short abbreviations, or corrected manually in `proofreading.json`.

- **`Sir` false positive**: The abbreviation `Sir` (Sirach) is also an English
  honorific. It will be italicized inside footnote citations such as
  `Sir Thomas More`. Remove the `<i>` tags manually in `proofreading.json`
  before committing.

- **Nested double quotes**: When a `"..."` quotation appears inside an outer
  `"..."` quotation (e.g. para 383), the simple state machine assigns wrong curly
  directions to the inner pair. Fix manually in `proofreading.json` by changing
  the inner pair to single curly quotes (U+2018 `'` / U+2019 `'`) before committing.
